## 1. 设计目标

DocQuery 管理后台服务于少量平台管理员、租户管理员和知识库管理员。

它不面向传统业务系统的客服、销售、员工或终端客户，也不承担传统业务系统的用户管理。

后台需要帮助管理员完成四件核心任务：

1. 创建业务应用并安全地管理应用凭证。
2. 创建知识库并将其授权给业务应用。
3. 上传、更新和删除文档，理解文档当前状态。
4. 查看哪个应用访问了哪个知识库。

页面设计优先级：

```text
边界清楚
> 状态清楚
> 操作可恢复
> 信息密度适中
> 视觉装饰
```

## 2. 设计原则

### 2.1 明确当前租户

每个管理页面都必须清晰显示当前租户。

管理员不能因为页面切换而误以为正在管理另一个租户的数据。

### 2.2 区分管理用户与业务应用

后台中的“应用”指接入 DocQuery 的业务系统，例如：

- 工单系统-production
- 客服系统-production
- 产品支持系统-testing

应用不是终端用户，也不是管理员账号。

### 2.3 凭证默认不可见

完整应用凭证只在创建时展示一次。

日常页面只显示：

- 凭证名称
- 前缀或摘要
- 状态
- 创建时间
- 最后使用时间

### 2.4 权限用“应用访问知识库”表达

页面不出现：

- 业务用户权限
- 部门权限
- 用户组权限
- 工单权限

MVP 需要清楚表达：

```text
哪个应用
→ 可以 READ、WRITE 或 READ_WRITE 哪个知识库
```

### 2.5 状态必须可理解

文档状态使用：

- 处理中（`PROCESSING`）
- 可检索（`READY`）
- 处理失败（`FAILED`）
- 删除中（`DELETING`）
- 已删除（`DELETED`）

状态旁边应提供中文解释和可执行操作，不能只显示技术代码。

### 2.6 高风险操作需要二次确认

以下操作必须确认：

- 撤销凭证
- 停用应用
- 撤销知识库授权
- 停用知识库
- 删除文档

确认弹窗必须说明影响范围。

## 3. 整体导航

### 3.1 桌面端布局

第一版采用典型 B 端桌面管理后台布局：

```text
┌──────────────────────────────────────────────┐
│ 顶栏：当前租户、环境提示、管理员菜单          │
├──────────────┬───────────────────────────────┤
│              │                               │
│ 左侧导航      │ 页面标题、说明、主要操作       │
│              │                               │
│ - 概览        │ 页面内容                      │
│ - 应用        │                               │
│ - 知识库      │                               │
│ - 处理任务    │                               │
│ - 访问审计    │                               │
│ - 设置        │                               │
│              │                               │
└──────────────┴───────────────────────────────┘
```

### 3.2 一级导航

#### 概览

查看租户当前资源和异常状态。

#### 应用

管理接入应用、凭证和知识库授权。

#### 知识库

管理知识库、文档、版本和授权应用。

#### 处理任务

集中查看处理中和失败的文档任务。

#### 访问审计

查看应用级调用记录和管理操作记录。

#### 设置

查看租户信息和基础设置。

## 4. 页面一：管理员登录

### 4.1 使用者

- 平台管理员
- 租户管理员
- 知识库管理员

### 4.2 用户任务

- 登录管理后台
- 进入自己有权管理的租户

### 4.3 页面内容

登录页：

- DocQuery 产品名称
- 简短说明：“为业务系统提供可靠的知识库管理与检索能力”
- 管理员账号
- 密码
- 登录按钮
- 错误提示区域

### 4.4 状态

- 默认
- 登录中
- 账号或密码错误
- 账号被停用
- 服务不可用

### 4.5 约束

- 页面不能暗示普通业务用户应该在此登录
- 第一版不展示注册入口
- 第一版不把应用凭证作为管理员登录凭证
- 首个平台管理员由部署人员通过一次性交互命令创建，管理后台不承担平台初始化

- 当前可用文档

### 9.5 页签

- 文档
- 应用授权
- 处理任务
- 访问审计
- 设置

### 9.6 文档表格

字段：

- 文档名称
- 当前版本
- 最新版本状态
- 更新时间
- 操作

示例：

```text
S1设备维修手册.pdf  v2  可检索（READY）         5分钟前
售后处理规范.docx   v3  处理中（PROCESSING）    1分钟前
常见故障说明.pdf     v1  处理失败（FAILED）      10分钟前
```

状态显示：

- 可检索（`READY`）：绿色状态标记，“当前版本可检索”
- 处理中（`PROCESSING`）：蓝色进度标记，“新版本处理中，旧版本仍可用”
- 处理失败（`FAILED`）：红色状态标记和失败摘要
- 删除中（`DELETING`）：灰色状态标记，“已停止检索，正在清理”

### 9.7 文档行操作

- 查看详情
- 上传新版本
- 查看版本历史
- 重试
- 删除

操作根据状态显示：

- 可检索（`READY`）：上传新版本、查看版本、删除
- 处理中（`PROCESSING`）：查看任务
- 处理失败（`FAILED`）：查看原因、重试、删除失败版本
- 删除中（`DELETING`）：查看删除状态

### 9.8 上传文档弹窗

内容：

- 拖拽或选择文件
- 支持格式提示：文本型 PDF、DOCX、TXT、Markdown
- 明确提示扫描 PDF、图片语义理解和 OCR 不属于第一版支持范围
- 文档名称
- 上传进度

上传受理后：

- 弹窗可以关闭
- 文档出现在列表中
- 状态显示 `PROCESSING`
- 页面提示“处理将在后台继续”

### 9.9 文档详情抽屉

包含：

- 文档信息
- 当前生效版本
- 版本历史
- 最近处理任务
- 失败摘要

版本历史字段：

- 版本
- 状态
- 是否生效
- 上传时间
- 生效时间
- 失败原因

### 9.10 新版本行为提示

上传新版本前明确提示：

> 新版本处理期间，当前版本仍然可用。新版本成功后自动切换；处理失败不会影响当前版本。

### 9.11 删除确认

必须提示：

- 文档确认删除后立即停止参与新检索
- 后台清理可能需要时间
- 第一版不承诺恢复

### 9.12 页面状态

- 正常
- 空知识库
- 上传中
- 文档处理中
- 文档失败
- 删除中
- 知识库停用
- 服务不可用

## 10. 页面七：知识库应用授权

### 10.1 使用者

- 租户管理员

### 10.2 用户任务

- 查看哪些应用可以访问当前知识库
- 给应用授予或修改 `READ`、`WRITE`、`READ_WRITE`
- 撤销应用授权

### 10.3 页面内容

标题：

```text
售后维修知识库 · 应用授权
```

说明：

```text
只有获得授权的业务应用才能访问该知识库。
传统业务终端用户权限由接入方自行管理。
```

### 10.4 授权表格

字段：

- 应用
- 环境
- 权限
- 应用状态
- 授权时间
- 操作

示例：

```text
工单系统-production  生产  READ  启用  2026-07-29
文档同步-production  生产  WRITE 启用  2026-07-29
```

### 10.5 添加授权

选择：

- 应用
- 权限：`READ`、`WRITE` 或 `READ_WRITE`

只能选择当前租户下启用的应用。

### 10.6 撤销授权确认

提示：

> 撤销后，工单系统-production 将无法继续查询售后维修知识库，但不会影响该应用访问其他已授权知识库。

### 10.7 页面状态

- 已有授权
- 没有授权
- 没有可用应用
- 应用已停用
- 撤销确认

- 删除文档

### 12.6 筛选

- 时间范围
- 应用
- 知识库
- 结果
- 操作
- 请求追踪标识

### 12.7 页面状态

- 正常有数据
- 空数据
- 筛选无结果
- 部分字段不可用
- 加载失败

## 13. 关键弹窗与反馈

### 13.1 凭证只展示一次

视觉优先级最高。

必须包含：

- 一次性展示提示
- 复制按钮
- 安全保存说明
- 确认已保存

### 13.2 撤销凭证

必须说明影响：

- 哪个应用
- 哪个凭证
- 是否立即生效
- 是否影响其他凭证

### 13.3 撤销知识库授权

必须说明：

- 哪个应用将失去访问
- 哪个知识库受到影响
- 不影响其他授权

### 13.4 上传新版本

必须说明：

- 当前版本继续可用
- 新版本成功后自动切换
- 新版本失败不影响旧版本

### 13.5 删除文档

必须说明：

- 立即停止参与检索
- 清理异步进行
- 第一版不承诺恢复

### 13.6 操作结果反馈

成功反馈应简洁：

- 应用已创建
- 凭证已撤销
- 授权已添加
- 文档已开始处理
- 重试已提交

失败反馈需要：

- 说明发生什么
- 说明是否可以重试
- 提供请求追踪标识

## 14. 视觉方向

### 14.1 风格

- 现代、克制的企业级 SaaS 管理后台
- 信息密度适中
- 清晰边框和卡片层级
- 不使用夸张渐变和大面积插画
- 不使用聊天产品的视觉语言

### 14.2 色彩

- 主色：偏冷的蓝色
- 背景：浅灰或灰白
- 卡片：白色
- 成功：绿色
- 处理中：蓝色
- 警告：橙色
- 失败：红色
- 删除中或停用：中性灰

### 14.3 字体与信息

- 中文无衬线字体
- 页面标题清晰
- 表格字段可扫描
- 状态标记同时使用颜色和文字
- 关键凭证使用等宽字体

## 15. 第一版页面验收

管理后台草图和后续实现需要满足：

- 管理员始终知道当前租户
- “应用”和“业务用户”不会混淆
- 应用凭证只在创建时完整展示
- 应用可以清楚查看已授权知识库
- 知识库可以清楚查看已授权应用
- 文档当前生效版本清晰
- 新版本处理中时旧版本仍可用的信息清晰
- 失败任务具有原因和重试入口
- 删除操作明确说明立即停止检索
- 审计以应用为主体
- 页面不出现业务用户、部门或用户组级授权

当管理员能够完成以下流程时，管理后台第一版产品链路成立：

```text
创建应用
→ 生成凭证
→ 创建知识库
→ 授权应用READ
→ 上传文档
→ 查看文档“可检索（READY）”
→ 查看应用访问审计
```
