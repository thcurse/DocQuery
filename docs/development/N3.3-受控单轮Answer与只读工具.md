## 1. 阶段目标

N3.3 开放正式服务面单轮回答接口：

```text
POST /api/v1/service/knowledge-bases/{knowledgeBaseId}/answer
```

它复用 N3.1 的可信授权、activeVersion 不可变快照和 Redis 幂等，以及 N3.2 的查询 Embedding、双路检索、RRF 和 canonical 原文证据，在同一次 `ANSWER` 执行上下文中完成：

- 原始问题首次检索；
- DeepSeek Answer Model 结构化回答；
- 证据不足时由 Java 控制有限的 Tool Calling 循环；
- 最终答案、Evidence ID 和 canonical 引用的本地严格校验；
- `ANSWERED` 与 `INSUFFICIENT_EVIDENCE` 两种成功终态。

“单轮”表示只有一个用户问题，不表示模型只能调用一次。`/answer` 不通过 HTTP 调用 `/retrieve`，也不竞争第二个 `RETRIEVE` 幂等任务；两者只共享内部检索能力。

## 2. 本阶段明确不做

- 不做多轮对话、会话历史、流式回答或 Answer 持久化；
- 不做多知识库、自动知识库路由、Reranker、语义 Chunk 或预检索生成式问题改写；
- 不提供联网、代码执行、数据库写入或任意扩展工具；
- 不把 LangChain4j 作为权限、幂等、预算或自主 Agent 控制器；
- 不新增数据库表、迁移、查询审计或检索评测；审计和效果/性能基线属于 N3.4；
- 不改变 N3.2 已验收的 `/retrieve` 外部契约和 `retrieve-ranking-v1`。

## 3. LangChain4j 边界

N3.3 使用现有 Java 依赖 LangChain4j 的底层 Chat 与 Tool Calling 适配，不引入 Python LangChain：

- 独立 `AnswerChatGateway` 和 Answer Model Bean；
- DeepSeek 官方 `deepseek-v4-flash`，服务端 Prompt 版本 `answer-agent-v1`；
- LangChain4j 只负责模型消息、Tool Schema 和响应适配；
- Java 固定权限上下文、版本快照、工具白名单、调用循环、预算、超时、续租、证据登记、引用校验和失败映射；
- Tool Schema 使用生产端点支持的普通 Function Calling，并由 Java 严格校验未知字段、必填字段、类型和范围；不依赖仅 Beta 端点可用且要求全部属性必填的供应商 `strict` 模式；
- canonical 文本是低信任数据，不能进入 System Prompt 或取得工具执行权限。

## 4. HTTP 契约

共同 Header：

```text
Authorization: Bearer dq_app_<keyId>.<secret>
Idempotency-Key: <1—128 个可见 ASCII 字符>
Content-Type: application/json
```

请求体：

```json
{
  "query": "退款申请需要哪些材料？",
  "mode": "HYBRID",
  "topK": 5
}
```

- `query`、`mode`、`topK` 复用 N3.2 的规范化和边界；
- `mode/topK` 只控制首次检索；调用方不能控制模型、Prompt、工具轮数或读取预算；
- 请求指纹使用 `answer-request-v1`，覆盖 knowledgeBaseId、规范化 query、mode、topK 和 `answer-policy-v1`；
- 每次请求及成功重放前都重新授权和固定当前 activeVersion 快照。

成功回答：

```json
{
  "queryExecutionId": "...",
  "knowledgeBaseId": 10,
  "status": "ANSWERED",
  "answer": "退款需要提供购买凭证。[E1]",
  "requestedMode": "HYBRID",
  "executedMode": "HYBRID",
  "degraded": false,
  "degradationReason": null,
  "citations": [{
    "evidenceId": "E1",
    "documentId": 20,
    "documentVersionId": 21,
    "versionNo": 1,
    "documentName": "退款规则.pdf",
    "headingNodeId": "heading-1",
    "headingPath": ["退款规则", "申请材料"],
    "pageNumber": 3,
    "blockId": "block-3",
    "text": "退款申请需提供购买凭证。",
    "truncated": false,
    "canonicalStart": 36,
    "canonicalEnd": 49,
    "sourcePosition": {"sourceType":"PDF","pageNumber":3,"pageBlockOrdinal":2,"pageCharacterStart":120,"pageCharacterEnd":133}
  }]
}
```

证据不足使用 HTTP `200`、`status=INSUFFICIENT_EVIDENCE`、`answer=null` 和空 citations。它是知识判断成功终态，不是依赖异常。

## 5. 四个只读工具

工具只在 Answer Agent 内部可见，不注册外部 HTTP 路由：

| 工具 | 模型可提交参数 | 服务端固定行为 |
| --- | --- | --- |
| `searchDocuments` | `query`、`limit<=10` | 当前 KnowledgeBase 与快照内执行检索并按文档聚合，必须作为首次工具调用 |
| `getDocumentOutline` | `documentId`、可选 `parentHeadingNodeId`、可选分页游标 | 返回 canonical 真实标题树，每次最多 100 个节点 |
| `searchWithinDocument` | `documentId`、`query`、`limit<=10` | 只搜索该 Document 的快照版本 |
| `readSection` | `documentId`、会话内 `sectionRef` | 读取最小授权范围；连续同页 block 聚合为一个页级 Evidence |

统一边界：

- 模型不能提交 tenantId、applicationId、knowledgeBaseId、documentVersionId、Bucket 或对象 Key；
- documentId 必须属于本次不可变快照；
- 工具查询最多 2,000 个 Unicode code point；
- `sectionRef` 只能由当前 Answer 会话中的检索或目录工具签发，模型不能提交 blockId、任意页码或 canonical offset；
- 命中导航子分区时精确读取该分区；命中真实叶子标题时读取完整叶子章节；
- 命中带子标题的父标题时只返回父标题自身正文和直接子标题，不默认展开整个子树；
- 问题跨多个子标题时，模型按需读取多个子标题；超过剩余安全预算时不生成固定切片；
- 所有可引用原文由 Java 登记为本次执行的 `E1/E2/...`；PDF 连续同页 block 合并为一个页级 Evidence；
- 工具失败不允许模型伪装为无结果。

## 6. Agent 执行预算

| 项目 | 上限 |
| --- | --- |
| 首次检索 | 模型首次必须调用 `searchDocuments` |
| 工具轮次 | 10 |
| 工具调用总数 | 20，每轮最多并行 2 次 |
| 正常模型调用 | 12 |
| 最终结构修复 | 最多额外 2 次 |
| 最小章节/导航范围与累计 canonical 原文 | 800,000 估算 token 安全预算 |
| Outline 累计节点 | 200 |
| 最终答案 | 4,000 Unicode code point |
| 最终引用 | 8 条、引用正文合计 16,000 字符 |
| 单次模型调用 | 120 秒 |
| Answer 总执行 | 300 秒 |

每个工具轮次后续租 Redis。上述是成本和安全硬上限，不是效果最优参数；模型不能扩大。到达预算时，已有合法终态正常返回，否则返回执行上限错误。

## 7. 最终输出与引用

模型最终输出内部严格 JSON：

```json
{"status":"ANSWERED","answer":"退款需要提供购买凭证。[E1]","citedEvidenceIds":["E1"]}
```

- 只允许 `ANSWERED`、`INSUFFICIENT_EVIDENCE` 和固定字段；
- `ANSWERED` 必须有非空 answer，且每个非空段落或列表项至少一个合法引用；
- Answer 中标记、`citedEvidenceIds` 和最终 citations 必须完全对应；
- 未知、重复、未使用或模型伪造的 Evidence ID 使输出无效；
- `INSUFFICIENT_EVIDENCE` 必须是 `answer=null`、空 Evidence ID；
- 允许一次结构修复，仍失败则 fail-closed；
- 回答默认使用问题语言，保留原始产品名、接口名和错误码；
- 不返回或保存思维过程，最终文本不允许 HTML。

最终 citation 一条对应一个页级或章节级 Evidence。用户语义是 Document、真实标题路径、PDF 物理页和逐字原文摘录；`blockId`、canonical range 等字段只为既有 API 兼容、服务端审计和精确重放保留，不交给模型，也不在后台普通引用视图展示。

## 8. Prompt Injection 防护

固定信任顺序是 Java 服务端策略 > System Prompt > Tool Schema > canonical 原文 > 模型输出：

- 原文作为结构化不可信数据传递，不拼接进 System Prompt；
- 文档中的工具调用、JSON、引用标记和“忽略指令”均没有执行权限；
- 未知工具、字段和越界参数由 Java 拒绝；
- 不向模型提供 Authorization、Credential、对象地址、数据库或跨范围标识；
- 所有工具重新校验当前 QueryAccessContext 和快照；
- Prompt、工具输入输出和模型输出均受长度与 Schema 限制；
- 默认日志不保存完整问题、原文、答案、Prompt、模型响应或思维过程；
- 本阶段保证权限、数据来源和可机械校验的引用边界；语义支持程度留给 N3.4 引用正确率评测。

## 9. 失败契约

| HTTP | 错误码 | 语义 |
| --- | --- | --- |
| `400` | `INVALID_ANSWER_REQUEST` | 请求字段或 Header 基础格式非法 |
| `401/404/409` | 沿用 N3.1/N3.2 | Credential、资源隐藏、幂等冲突 |
| `503` | `QUERY_IDEMPOTENCY_UNAVAILABLE` | Redis 无法提供幂等承诺 |
| `503` | `QUERY_EMBEDDING_UNAVAILABLE` | 显式 SEMANTIC 无有效查询向量 |
| `503` | `SEARCH_UNAVAILABLE` | Elasticsearch 检索失败 |
| `503` | `EVIDENCE_UNAVAILABLE` | canonical 或地址完整性失败 |
| `503` | `ANSWER_MODEL_UNAVAILABLE` | Chat 超时、限流或供应商异常 |
| `503` | `ANSWER_OUTPUT_INVALID` | 修复后仍为非法工具参数、JSON 或引用 |
| `503` | `ANSWER_EXECUTION_LIMIT_EXCEEDED` | 超出工具轮数或调用预算 |
| `503` | `ANSWER_EXECUTION_TIMEOUT` | 超过 120 秒总时限 |

`ANSWERED` 和 `INSUFFICIENT_EVIDENCE` 写入 Redis 并允许精确重放；所有 4xx/5xx 只释放当前 owner，不缓存失败。

## 10. 验收点

1. 授权应用可获得带 canonical 引用的单轮回答；
2. 初始证据不足时四个只读工具可以受控补充搜索和阅读；
3. 无充分证据返回 `200 INSUFFICIENT_EVIDENCE`，不编造答案；
4. 工具无法访问跨 Tenant、跨 KnowledgeBase、历史版本或快照外文档；
5. 文档提示注入不能覆盖策略、调用未知工具或扩大范围；
6. 轮数、调用量、字符量和总时限均 fail-closed；
7. 非法工具参数、结构和引用只允许一次受控修复；
8. Chat 失败不影响独立 `/retrieve`，Answer 返回明确 503；
9. HYBRID/SEMANTIC 继续遵循 N3.2 查询 Embedding 降级规则；
10. 相同 Answer 幂等请求只执行一次昂贵链路并精确重放；撤权和版本切换阻止旧结果重放；
11. canonical 损坏、ES 地址不一致和未知 Evidence ID 不能返回回答；
12. 四种文档格式的引用位置均可展示；
13. 使用真实 MySQL、SeaweedFS、Redis、Elasticsearch、Fake Query Embedding 和脚本化 Fake Answer Model 完成端到端测试；
14. 提供显式开启的真实 DeepSeek Tool Calling 小样本冒烟，默认回归不调用收费供应商；
15. N0—N3.2 全量回归继续通过，数据库仍为 V1—V8；
16. 不出现多轮聊天、通用 Agent、流式回答、审计表或 N3.4 评测占位。

- 已开放 `/answer` Controller、独立 `AnswerService`/`AnswerChatGateway` 和 DeepSeek LangChain4j 低层适配；未通过 HTTP 调用 `/retrieve`，同一次 `ANSWER` 复用已授权、已固定快照的内部检索核心。
- Java 已实现四工具白名单、字段/范围校验、不透明 Outline 游标、3 轮/6 调用/每轮 2 调用上限、模型/修复/字符/引用/总时限预算，以及每轮工具后的 Redis 续租。
