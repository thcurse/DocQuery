# DocQuery N3.2 BM25、KNN、RRF 与原文引用

> 状态：已实现、验证并经用户验收；阶段已关闭  
> 前置阶段：N0—N3.1 均已实现、验证并经用户验收  
> 上游依据：[`DocQuery 产品设计 v0.1`](../product/01-DocQuery-产品设计-v0.1.md)、[`检索生成与查询技术选型`](../technical-decisions/02-03-检索生成与查询技术选型.md)、[`N3.1 查询授权、版本快照与 Redis 幂等`](./N3.1-查询授权与Redis幂等.md)

## 1. 阶段目标

N3.2 开放第一条正式服务面检索接口：

```text
POST /api/v1/service/knowledge-bases/{knowledgeBaseId}/retrieve
```

它复用 N3.1 已验收的 Application Credential、READ Grant、activeVersion 不可变快照和 Redis 幂等，在同一可信范围内完成：

- 原始问题的 Query Embedding；
- Evidence BM25 与 Navigation KNN 并行召回；
- Java RRF、章节聚合、稳定去重和 Top-K；
- `canonical.jsonl` 完整性校验、原文读取和引用组装；
- `KEYWORD`、`SEMANTIC`、`HYBRID` 三种明确检索模式及受控降级。

## 2. 本阶段明确不做

- 不实现 `/answer`、Chat Model 回答、Agent 或工具调用；
- 不进行生成式查询改写，BM25 和 Query Embedding 都使用同一原始查询；
- 不实现多知识库、会话历史、Reranker、语义 Chunk 或独立向量库；
- 不新增数据库表、迁移或查询审计；
- 不把 Redis 用作 Credential、Grant、activeVersion、ES 结果或 canonical 正文缓存；
- 不执行 N3.4 的 Recall/MRR/nDCG 调参和性能承诺。

## 3. HTTP 契约

共同 Header：

```text
Authorization: Bearer dq_app_<keyId>.<secret>
Idempotency-Key: <1—128 个可见 ASCII 字符>
Content-Type: application/json
```

请求体：

```json
{
  "query": "退款需要满足什么条件？",
  "mode": "HYBRID",
  "topK": 5
}
```

规则：

- `query` 去除首尾空白后必须非空，最多 2,000 个 Unicode code point；不做大小写折叠或模型改写；
- `mode` 可选，默认 `HYBRID`，允许 `KEYWORD`、`SEMANTIC`、`HYBRID`；
- `topK` 可选，默认 5，范围 1—20；
- 调用方不提交 `tenantId`、`applicationId`、activeVersion、候选数、字段权重或 RRF 常数；
- 请求指纹使用 `retrieve-request-v1`，覆盖 knowledgeBaseId、规范化 query、mode、topK 和 `retrieve-ranking-v1`。

成功响应包含稳定的 `queryExecutionId`、请求/实际模式、降级状态和结果。每个结果以 `documentVersionId + headingNodeId` 为章节地址，包含文档、版本、真实标题路径、命中通道、通道排名以及最多三条 canonical 原文证据。关键词高亮使用结构化片段，不返回可执行 HTML。

原始 BM25 分数、向量相似度和内部 RRF 分值不是稳定外部契约。

## 4. 固定执行顺序与权限边界

```text
Credential/Application/Tenant 当前状态
→ KnowledgeBase 当前状态和 READ/READ_WRITE Grant
→ 单 SQL activeVersion 不可变快照
→ Redis claim
→ BM25 与（Query Embedding → KNN）并行
→ Java RRF
→ canonical 原文读取和校验
→ Redis complete
→ 返回响应
```

- 每次请求和成功重放都先重新授权、重新读取快照；
- Evidence 与 Navigation 查询都在 ES 查询内部过滤可信 `tenant_id`、`knowledge_base_id` 和同一组 `document_version_id`；
- 禁止全局召回后在 Java 删除其他租户、其他知识库或历史版本；
- Redis replay 绑定 N3.1 的快照指纹，版本切换后不能返回旧结果；
- canonical 读取只能使用快照中的版本及其 MySQL 清单，不能接受客户端或模型提供的对象地址。

## 5. Query Embedding

- 使用与 N2.4 导航向量相同的阿里云百炼 `qwen3.7-text-embedding` 和 2,560 维空间；
- 使用独立 `QueryEmbeddingGateway` 和独立 EmbeddingModel Bean，固定 `text_type=query`、`output_type=dense`；
- 不复用 N2.4 固定 `text_type=document` 的 `NavigationEmbeddingGateway`；
- 输出必须恰好 2,560 维、全部为有限值且不是全零；
- `KEYWORD` 不调用 Embedding；`HYBRID` 的 Embedding/KNN 失败允许明确降级为 `KEYWORD`；显式 `SEMANTIC` 失败返回依赖异常。

## 6. 双路召回与排名

### 6.1 BM25

- 查询 Evidence 的 `text`、`text.standard`、`heading_path`、`heading_path.standard`、`document_title` 和 `document_title.standard`；
- 基线权重依次为 `4.0/3.0/2.0/1.5/1.2/1.0`；
- 使用 `best_fields`、`OR`，候选数固定为 50；
- 同一章节多个 block 命中时，章节通道排名取最靠前 block，命中 block 列表用于最终证据优先级。

### 6.2 KNN

- 查询 Navigation `embedding`，`k=20`、`numCandidates=100`；
- `HEADING_NODE` 直接映射真实章节；
- `DOCUMENT_PROFILE` 只提供文档级导航信号：优先附着到同文档的 BM25/NODE 章节，不把模型卡摘要作为原文结果；只有 canonical 中唯一根章节的无标题文档可以落到根章节；
- N3.2 不拍脑袋冻结业务相关性阈值，向量相似度阈值留给 N3.4 固定评测集；无快照、通道无命中或没有可验证原文时正常返回空结果。

### 6.3 RRF

- 融合键：`documentVersionId + headingNodeId`；
- `rrfK=60`，关键词与语义等权；
- 公式：`1/(60 + keywordRank) + 1/(60 + semanticRank)`；
- 并列时依次使用最优单通道排名、documentVersionId、headingNodeId，保证重放和测试可重复；
- 最终按融合顺序截取请求 `topK`，不直接相加 BM25 和 cosine 原始分数。

上述参数属于 `retrieve-ranking-v1` 基线。N3.4 可以基于评测创建新算法版本，不能静默改变幂等请求语义。

## 7. canonical 原文与引用

- 最终结果只能来自 `canonical.jsonl`；ES `_source.text` 和检索卡只提供候选地址；
- 每个最终文档版本在一次请求内最多读一次 canonical 对象；
- 完整读取并复核 Bucket、对象大小、对象 SHA-256、documentVersionId、canonical text SHA、Header/Footer、计数和结构；
- 校验 ES 返回的 blockId、headingNodeId、ordinal、canonical range 与 canonical 一致；
- BM25 章节优先返回实际命中 block，再按 ordinal 补同一 continuation group 或章节内相邻正文；
- 纯 NODE 语义命中返回该真实章节起点开始的最多三条非空原文块；
- 每条结果最多 3 个 EvidenceBlock、12,000 个字符；全部结果正文总计最多 80,000 个字符，保证低于 N3.1 Redis 1 MiB 限制；
- 任一最终命中版本的 canonical 缺失、损坏或地址不一致，整次请求 fail-closed，不返回未经验证的 ES 文本。

## 8. 失败契约

| HTTP | 错误码 | 语义 |
| --- | --- | --- |
| `400` | `INVALID_RETRIEVE_REQUEST` | query、mode、topK 或 Header 基础格式错误 |
| `401` | `APPLICATION_CREDENTIAL_INVALID` | 沿用 N3.1 统一认证失败 |
| `404` | `KNOWLEDGE_BASE_NOT_AVAILABLE` | 沿用 N3.1 资源隐藏 |
| `409` | `IDEMPOTENCY_CONFLICT` / `IDEMPOTENCY_CONTEXT_CHANGED` / `REQUEST_IN_PROGRESS` | 沿用 N3.1 幂等冲突 |
| `503` | `QUERY_IDEMPOTENCY_UNAVAILABLE` | Redis 无法提供幂等承诺 |
| `503` | `QUERY_EMBEDDING_UNAVAILABLE` | 显式语义检索无法生成有效查询向量 |
| `503` | `SEARCH_UNAVAILABLE` | 所需 ES 通道不可用或索引契约错误 |
| `503` | `EVIDENCE_UNAVAILABLE` | canonical 对象、清单或地址完整性失败 |

`HYBRID` 只有语义支路失败且 BM25 成功时返回 `200`，`executedMode=KEYWORD`、`degraded=true` 和稳定降级原因。业务执行失败只释放当前 Redis owner，不缓存错误响应。

## 9. 验收点

1. 正确 Credential 和 READ/READ_WRITE Grant 可以调用真实 `/retrieve`；N3.1 的认证隐藏和状态即时复查保持成立；
2. `KEYWORD`、`SEMANTIC`、`HYBRID` 三种模式可重复执行，KEYWORD 不调用 Embedding；
3. Query Embedding 使用 `query` 类型并严格校验 2,560 维；
4. HYBRID 中 BM25 与 Embedding/KNN 两支并行，语义支路失败只产生明确关键词降级；
5. 两个 ES 查询都携带相同 Tenant、KnowledgeBase 和 activeVersion `terms` 过滤；
6. 历史 READY、PROCESSING、FAILED、跨租户和未授权文档不能召回；
7. RRF、章节聚合、去重、并列规则和 Top-K 结果稳定；
8. 返回原文逐字来自 canonical，标题路径和 PDF/DOCX/Markdown/TXT 位置正确；
9. 篡改 ES 文本不能改变返回原文，篡改 canonical 或地址必须返回 `EVIDENCE_UNAVAILABLE`；
10. 空知识库和无结果返回 `200` 空数组，不伪装依赖异常；
11. 相同幂等请求并发只执行一次昂贵链路，成功后精确重放；授权撤销和版本切换仍阻止重放；
12. 使用真实 MySQL、SeaweedFS、Redis、Elasticsearch 和 Fake Query Embedding 完成 HTTP 端到端验证；默认回归不调用收费供应商；
13. N0—N3.1 全量回归继续通过，数据库仍为 V1—V8，未出现 `/answer`、Agent、审计或迁移占位实现。
