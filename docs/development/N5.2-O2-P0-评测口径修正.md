# N5.2-O2-P0 评测口径修正

> 状态：`PENDING_ACCEPTANCE / COMPLETED`
> 开始授权：用户于 2026-08-22 确认筛选问题并处理文档页码问题后明确说“开始吧”。

## 1. 最小范围

- 不修改检索、解析、索引或外部 API；
- 不调用 DeepSeek、Embedding、`/retrieve` 或 `/answer`；
- 不覆盖冻结的 R1、R2、P3 原始结果；
- 只从64道既有公开 `ANSWERABLE` 题中按题目文本筛选无需 `documentIds` 即可理解和定位来源的高置信子集；
- 不改写题目，不生成自制题目；
- 使用 PDF Page Labels 将公开集 Gold 印刷页码转换为 DocQuery 返回的一基物理页码；
- 相同 SHA-256 的文档按同一内容来源计分。

## 2. 筛选口径

题目至少包含一种可从题目本身识别来源的锚点：命名实体、组织、产品、缩写、明确章节名或显著短语。以下情况排除并单列：

- 只依赖“this report / this paper / this slide / this case”等被省略的单文档上下文；
- 主要依赖图片计数或视觉理解；
- Gold 页无法由 PDF Page Labels 唯一映射；
- 公开数据集文件内容与题目明显不一致。

筛选只依据题目和数据集事实，不依据 R1/R2/P3 是否命中。结果已经被观察，因此该子集只能作为修正口径后的诊断，不能重新包装成 held-out 分数。

## 3. 页码规则

- Gold 数字解释为 PDF 的 Page Label；
- 通过 PDF `/PageLabels` 展开为每个物理页的标签；
- 每个 Gold 标签必须且只能对应一个一基物理页，否则排除；
- DocQuery 返回页仍保持物理页码，产品模型和 API 不增加新字段。

## 4. 当前进展

## 6. 页码修正的实际影响

25题中只有两题出现非恒等 Page Label：

- `mmlongbench-0093`：印刷页11/12对应物理页13/14；原算法把物理页11/12误记为命中，修正后从命中变为未命中；
- `mmlongbench-0908`：印刷页28对应物理页30；原算法把正确的物理页30记为未命中，修正后从未命中变为命中。

一正一负恰好抵消，因此修正前后宏平均均为0.82；这不代表页码修正没有作用。PDF Page Labels 和实际页面版面均已核对。

## 7. 结论与边界

在问题本身具备来源定位信息、仍不传 `documentIds` 的25题子集上，现有关键词 Evidence BM25 + 导航卡向量 HYBRID 已达到 Doc Hit@5 0.96、Page Coverage@10 0.82、MRR@10 0.92。该结果不支持继续扩建检索架构。

该子集是在 R1/R2 结果已经执行后按题目文本复核得到，只能作为可信度更高的诊断，不能冒充新的 held-out 成绩。原 R2/P3 报告保留，不被覆盖。
