# N5.3-A9 标准 Agent 循环与完成检查

## 1. 目标与边界

A9 只修正单轮 Answer 内部执行链路，不引入跨请求 Conversation、会话记忆、流式输出、更多业务工具或 20/80 题 Answer 扩测。

目标是解决三类已证实问题：同轮多个工具被本地拒绝、模型第一次给出最终文本后无法在原状态继续、拿到局部证据后漏搜/漏项但仍被接受。

## 2. 设计依据

- LangChain4j `AiServices` 默认顺序执行同一响应内的多个工具调用；`maxToolCallingRoundTrips` 默认值为 100。A9 不再自行限制“单轮最多几个工具”。
- OpenAI Agents runner、Anthropic evaluator-optimizer 和 LangGraph 的共同结构是：模型步骤、工具反馈、状态续接、完成/停止判断分离，而不是一次工具调用后立即终止。
- DocQuery 采用混合方案：LangChain4j 管理模型与工具消息循环；应用层保留权限快照、引用注册、幂等租约、总预算和完成检查。

## 3. 已实现链路

1. Java 先按原问题执行一次受控 Retrieve，建立初始候选池和 D#/S#/E# 注册表。
2. 每个 HTTP Answer 请求创建一个独立的 LangChain4j `MessageWindowChatMemory`，只在该请求内部保存 Agent 消息历史。
3. Agent 只有 `search` 和 `open`；同一模型响应中的多个工具按框架默认顺序全部执行。
4. Agent 给出候选最终 JSON 后，应用层先做格式、引用和权限边界校验。
5. 独立、无工具的完成检查器返回 `PASS` 或带缺项反馈的 `CONTINUE`。
6. `CONTINUE` 反馈进入同一个 AgentRun，继续沿用原工具历史，不新建 Agent。
7. 拒答前至少需要初始查询之外两次不同搜索；发现文档时至少打开一个 D#/S# 引用。
8. v7 新增 ANSWERED 验证条件：接受回答前至少完成一次区别于初始问题的成功搜索。它用于发现重复标签、同名章节和遗漏的匹配事实，不负责确定性计算。

保险丝是异常保护，不是正常循环目标：100 个工具轮次、200 次工具调用、120 次模型调用、8 次完成检查、300 秒总超时、18 万 canonical 原文估算 token。

## 4. 固定 5 题 v6 真实复验

运行目录：`evaluation/mmlongbench-docquery-v1/reports/n5.3-a9-standard-agent-targeted-revalidation/`

- 5/5 HTTP 200，5/5 `ANSWERED`，0 次执行上限错误。
- 人工正确 3/5：0562、0607、0937 正确；0831、1032 错误。
- 0831 错在使用页 7-8 的局部同名任务，未找到 Gold 页 16 的 Quarter 3 汇总。
- 1032 错在只回答 133.2，遗漏 120.1，未得到 253.3。
- 三道正确题的 Agent 工具调用数分别为 4、5、2；两道错误题均为 0。

因此 v6 结论为失败，但证明框架循环和上限修正有效。剩余根因是 Agent 可以完全绕过工具，而完成检查器无法审查尚未被搜索登记的证据。

## 5. v7 状态与下一验收点

v7 已加入 ANSWERED 前的不同查询验证搜索门槛，并通过：

- 单元测试 71/71，0 失败、0 错误，2 个真实供应商 smoke 默认跳过；
- `RetrieveIT` 9/9。

尚未对 v7 追加付费请求。下一次得到明确授权后，只复验冻结的固定 5 题并按以下条件验收：

- 5/5 HTTP 成功且无执行上限错误；
- 0831 必须定位 Quarter 3 的三个准备项，不得用页 7-8 的局部同名内容替代；
- 1032 必须同时覆盖 133.2 和 120.1，并回答 253.3；
- 每题 ANSWERED 至少有一次成功的不同查询验证搜索；
- 逐题人工核对答案、引用支持和 Gold 页覆盖，不以 `ANSWERED` 状态代替正确性。

## 6. v7 固定 5 题真实复验结果

运行目录：`evaluation/mmlongbench-docquery-v1/reports/n5.3-a9-v7-standard-agent-targeted-revalidation/`

- 冻结范围仍为 5 个逻辑用例；评测脚本对失败的 1032 做了一次内置 HTTP 重试，因此共 6 次 HTTP 尝试。
- 4/5 用例 HTTP 200，1032 为 `ANSWER_MODEL_UNAVAILABLE`；没有执行上限错误。
- 严格人工正确仍为 3/5：0562、0607、0937 正确。
- 0831 从 v6 的一个参考动作提升为包含三个参考动作，并实际执行 8 次工具调用；但它仍使用页 7-8 的单元内容、混入额外 Unit 9 任务、没有按要求返回三项列表，也没有引用 Gold 页 16，因此冻结验收点不通过。
- 1032 首次尝试执行 1 次工具调用、6 次模型调用后映射为 `ANSWER_MODEL_UNAVAILABLE`；脚本重试在约 1 秒内同码失败。请求后后端健康检查仍为 200，不能归因为本地执行上限。

结论：v7 的“ANSWERED 前必须验证搜索”机械条件生效，但固定 5 题仍未通过，A9 不关闭。不得据此扩大 Answer 评测范围。
