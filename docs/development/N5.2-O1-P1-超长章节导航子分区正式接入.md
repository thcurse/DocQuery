## 1. 目标

把 P0 已验收的“模型语义候选 + 本地连续范围选择”接入正式入库和查询链路，解决超长无子标题章节只有一张粗粒度导航卡、纯语义命中后容易从章节开头取证的问题。

本阶段不重新切分 Evidence 原文，不修改 canonical 真实标题树，也不执行真实供应商调用、文档重入库、R2 重评或 Answer 评测。

## 2. 用户可感知规则

- 普通章节不增加任何标题；
- 已有真实子标题的父章节不生成派生导航标题；
- 只有估算超过 64K token 且没有真实子标题的章节才生成；
- 每个超长章节最终生成 2—6 个导航分区，无法在 6 个以内满足约束时失败关闭；
- 无真实标题的超长文档保留 DocumentProfile，并增加 2—6 个文档内导航分区；
- 派生标题是内部检索导航，不冒充 PDF/DOCX 的真实标题，不写入 canonical 标题树。

## 3. 入库链路

```text
canonical 真实标题树
→ 找出超过 64K 估算 token 的叶子章节
→ DeepSeek 读取完整章节并返回语义边界候选
→ 本地有界动态规划选择最少 2—6 个连续范围
→ 每个最终范围生成一张检索卡和一条导航向量
→ retrieval.jsonl schema v2
→ Elasticsearch Navigation 投影
```

分区边界只能来自模型返回的 canonical block ordinal。本地 token 规则只判断范围是否可行，不能创建固定窗口边界。未入选候选不保存、不向量化、不成为检索结果。

## 4. 数量与预算边界

- 触发阈值：64,000 估算 token；
- 单分区下限：8,000 估算 token；
- 单章节最终分区：2—6；
- 模型候选响应安全上限：256；
- 多语言估算器 `mixed-char-v1`：ASCII 每 4 字符约 1 token，非 ASCII 每 code point 约 1 token，按 canonical block 可加和；
- 检索卡单次原文字符安全上限提升到 256,000，避免已经形成的英文长分区再次被不必要地拆成大量临时批次；
- 单文档累计原文、最大卡片数和最大 Chat 调用数继续受既有全局预算限制。

## 5. Retrieval Artifact v2 与兼容

`retrieval.jsonl` schema v2 为节点增加内部类型：

- `HEADING_NODE`：原有完整真实章节卡；
- `HEADING_SUBPARTITION`：属于某个真实章节的派生导航分区卡。

派生卡使用稳定 ID：

```text
{documentVersionId}:rsp:{真实标题稳定顺序}:{分区顺序}
```

每张派生卡仍保存所属真实 `headingNodeId`、连续 block/canonical/source 范围、导航语义字段和 Embedding。生成指纹新增开关、估算器、阈值、分区数量和候选上限。

Reader/Validator 同时接受 schema v1 旧章节卡和 schema v2 新卡；旧活动版本无需立即重新入库，查询链路保持兼容。Elasticsearch 现有 `card_type`、标题和范围字段能够表达新卡，因此本阶段不升级 Mapping。

## 6. 查询链路

- `HEADING_NODE` 仍必须与完整真实章节范围一致；
- `HEADING_SUBPARTITION` 必须完全包含在所属真实章节内，并与 canonical 首尾 block 位置一致；
- 同一真实章节的多张向量卡先按 `headingNodeId` 折叠，再使用紧凑语义排名参与 RRF，避免导航标题多的章节挤占召回名额；
- 有 BM25 命中时继续优先返回精确关键词原文；
- 纯语义命中派生卡时，只在该派生卡的连续 canonical 范围内选择 Evidence，不再从整个超长章节开头取证；
- 外部 `/retrieve` 仍返回真实标题路径与 canonical 原文，不把导航标题或检索卡摘要当成引用证据；
- 排名契约升级为 `retrieve-ranking-v2`，避免旧幂等结果与新排名语义混用。

## 7. 失败处理

- 边界 JSON 无效、候选超过 256、范围不连续或无法满足 2—6 段与 64K 上限时，最多执行一次现有结构纠正后失败关闭；
- 超长到至少需要 7 个分区时返回 `RETRIEVAL_GENERATION_LIMIT_EXCEEDED`；
- 不静默退回粗粒度整章卡并标记 READY；
- 新版本失败时，已有活动版本继续提供服务；
- 原文、模型原始响应和密钥不进入异常或日志。

## 8. 非目标

- 不生成大规模新数据集；
- 不把普通章节改为固定 token chunk；
- 不持久化模型未入选候选；
- 不修改公开 Retrieve/Answer DTO、OpenAPI 或后台页面；
- 不自动重建测试科技的 100 份文档；
- 不执行真实 DeepSeek、百炼 Embedding、R2 或 Answer 评测。
