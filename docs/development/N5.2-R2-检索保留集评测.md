# N5.2-R2 检索保留集评测

> 状态：`IN_PROGRESS`
> 开始授权：用户于 2026-08-20 明确说“确认按以上范围执行 N5.2-R2”
> 上游阶段：[`N5.2-R1 检索 PILOT`](./N5.2-R1-检索PILOT.md)

## 1. 目标与冻结决策

R2 使用 R1 从未执行的 54 道可回答保留题，对当前生产候选检索模式执行正式 held-out 评测。

- R1 已完成 KEYWORD、SEMANTIC、HYBRID 三模式对照；R2 只执行 R1 表现最好的 `HYBRID`。
- 不使用唯一一次参数调整机会，继续使用 `retrieve-ranking-v1` 与 `topK=10`，避免针对 10 道 PILOT 过拟合。
- 54 道题记录在 `evaluation/mmlongbench-docquery-v1/n5.2-r2-heldout-selection.json`，确定性定义为全部 64 道 `ANSWERABLE` case 排除冻结的 10 道 R1 case，再按 `sourceRowIndex` 升序排列。
- R2 共 54 个正式 `/retrieve` 逻辑请求，不调用 `/answer`、DeepSeek，不执行 16 道不可回答题，也不执行并发压测。

## 2. 指标

主指标：

1. `Document Hit@5`：Top5 检索卡中是否出现 Gold 来源文档；当前每题只有一个 Gold 文档，数值等价于原 `Document Recall@5`。
2. `Evidence Page Coverage@10`：Top10 中正确来源文档命中的不同 Gold 页数 / 该题全部 Gold 页数；先逐题计算，再对 54 题做宏平均。
3. `MRR@10`：Top10 中第一个正确来源文档检索卡排名的倒数。

补充诊断：

- `Document Hit@1`、`Document Hit@10`；
- `Any Gold Page Hit@10`：至少命中一个 Gold 页；对应 R1 原名 `Evidence Page Recall@10`；
- `All Gold Pages Hit@10`：命中该题全部 Gold 页。

同页码只在 Gold 来源文档中计数；错误文档的相同页码不算命中。TopK 指服务返回的检索卡位置，不是去重后的文档数量。

## 3. 执行和失败处理

- 使用测试科技租户的评测应用、READ Grant 与 KnowledgeBase ID `1`，凭证只从 Git 忽略的本地环境配置读取。
- 幂等键固定包含 `n5.2-r2-heldout-v1`、caseId 和 `HYBRID`；中断后复用相同键并从已落盘结果继续。
- `429`、传输超时或 `5xx` 最多重试一次；鉴权、参数、资源隐藏和幂等冲突不重试。
- HYBRID 降级结果单独计数，不进入正式 held-out 质量总体。
- 每题保存 HTTP 状态、端到端延迟、请求/执行 ID、降级信息、稳定文档映射、排名和页码；不保存 evidence 正文或 Credential。

## 4. 报告边界

- `R2 held-out 54` 是正式主结果。
- `R1+R2 64` 只作为补充描述，因为 R1 已用于选择 HYBRID，不能冒充纯 held-out 分数。
- 54 个顺序请求的 P50/P95 只代表当前单请求外部 HTTP 样本，不代表并发性能或容量。
- 当前公开契约不返回 Query Embedding 精确 Token；只记录逻辑调用上限，不虚构 Token 或金额。

产物目录固定为 `evaluation/mmlongbench-docquery-v1/reports/n5.2-r2-heldout/`：

- `raw-results.jsonl`：54 个脱敏逐题结果；
- `report.json`、`report.md`：R2 held-out 主报告；
- `combined-64.json`：带选择偏差声明的 64 题补充汇总。

## 5. 验收点

1. 54 题选择及其输入指纹在首个 R2 请求前落盘；
2. 54 个逻辑请求均取得可解释终态，重试与降级不被隐藏；
