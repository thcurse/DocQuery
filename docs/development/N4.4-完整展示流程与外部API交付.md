# DocQuery N4.4 完整展示流程与外部 API 交付

> 状态：原冻结范围与租户管理员管理补充范围均已实现、验证并经用户验收，N4.4 已关闭  
> 前置阶段：N0—N4.3 已实现、验证并经用户验收  
> 本阶段门禁：用户已于 2026-08-15 明确说“确认开始 N4.4”，并于同日明确说“确认补充 N4.4 租户管理员管理”

## 1. 阶段目标

N4.4 不增加新的企业身份模型，而是把已经存在的管理、文档、查询和审计能力收敛为一个可在浏览器完整演示、可由传统业务后端按稳定文档接入的产品流程：

```text
平台管理员创建 Tenant
→ 租户管理员创建 Application、KnowledgeBase、Credential 和 Grant
→ 上传文档并查看 Version / ProcessingJob
→ 文档进入 READY
→ 业务应用使用真实 Application Credential 调用 Retrieve / Answer
→ 返回 canonical 原文证据或带引用单轮答案
→ 租户管理员查看对应查询审计
```

## 2. 管理后台范围

### 2.1 文档生命周期

- 在 KnowledgeBase 详情中提供文档列表、名称/状态筛选和分页；
- 支持 PDF、DOCX、TXT、Markdown 首次上传；
- 提供文档详情、activeVersion、latestVersion、版本历史和最近处理任务；
- 支持已有文档上传新版本；
- 展示处理中旧 activeVersion 继续服务、失败原因及可重试性；
- 支持最终失败 ProcessingJob 的人工重试；
- 支持整个逻辑 Document 的不可恢复删除、删除状态及删除失败人工重试；
- 使用定时重新读取后端事实，不引入 WebSocket 或前端伪造状态。

### 2.2 服务 API 调试

- 租户管理员在独立“API 调试”页面选择自身 Application 和已获 READ/READ_WRITE Grant 的 KnowledgeBase；
- 页面调用真实 `/retrieve`、`/answer`，不增加管理员旁路或内部测试接口；
- Credential 由管理员手工粘贴，只存在于组件局部内存；不进入 URL、Web Storage、TanStack Query Cache 或日志；
- 每次调用生成新的 `Idempotency-Key`，允许输入 `X-DocQuery-Trace-Id` 和 `X-DocQuery-Actor-Ref`；
- 展示请求执行 ID、实际模式、降级信息、原文证据、回答状态和 canonical 引用。

### 2.3 查询审计

- 提供只读审计列表和详情；
- 支持 Application、KnowledgeBase、操作类型、结果和请求标识筛选；
- 页面只展示 N3.4 已有最小化审计事实，不展示原问题、回答正文或 canonical 原文。

### 2.4 使用说明

- 管理后台向平台管理员和租户管理员共同提供“使用说明”页面，集中展示角色分工、租户准备、资源准备、`knowledgeBaseId` 获取、Credential、Grant、请求 Header、Retrieve/Answer 示例、幂等和错误处理；
- 页面提供 OpenAPI YAML 和 Postman Collection 下载；
- 同一内容在仓库中版本化，页面不是唯一文档副本；
- Application、KnowledgeBase 和文档详情保留稳定 ID，并提供复制入口。

### 2.5 租户管理员管理补充

- 平台管理员在 Tenant 详情中查看该租户全部 `TENANT_ADMIN`；
- 创建 Tenant 时仍原子创建首个租户管理员；后续可由平台管理员新增其他租户管理员；
- 支持单独启用、停用租户管理员和设置新密码，不提供旧密码读取或明文回显；
- 停用最后一个有效租户管理员必须拒绝，避免产生无法进入的活动 Tenant；
- 密码重置和账号状态变化更新账号版本，既有管理员 Session 在下一次请求时立即失效；
- 登录名继续全平台唯一并统一规范化为小写；不新增公开注册、邮件邀请、删除管理员或复杂租户内角色。

## 3. 外部服务契约

- 只冻结已经实现的两个服务路由：
  - `POST /api/v1/service/knowledge-bases/{knowledgeBaseId}/retrieve`
  - `POST /api/v1/service/knowledge-bases/{knowledgeBaseId}/answer`
- `Authorization` 固定为 `Bearer dq_app_<keyId>.<secret>`；
- `Idempotency-Key` 为每个逻辑请求的必填高熵标识，同一 Key 仅可重放同一请求；
- 可选透传 `X-DocQuery-Trace-Id` 和 `X-DocQuery-Actor-Ref`，响应返回 `X-DocQuery-Request-Id`；
- 请求字段为 `query`、`mode`、`topK`；`mode` 为 `KEYWORD`、`SEMANTIC` 或 `HYBRID`；
- OpenAPI、页面说明和示例必须与真实 DTO/VO、认证隐藏、Grant、activeVersion 快照、降级和错误码保持一致；
- 不承诺 SDK、流式响应或多轮会话兼容性。

租户管理员补充使用以下管理面契约，且全部只允许 `PLATFORM_ADMIN`：

- `GET /api/admin/v1/tenants/{tenantId}/administrators`：分页列出；
- `POST /api/admin/v1/tenants/{tenantId}/administrators`：使用 `loginName`、`password` 新增；
- `PATCH /api/admin/v1/tenants/{tenantId}/administrators/{administratorId}`：使用 `status` 启停；
- `PUT /api/admin/v1/tenants/{tenantId}/administrators/{administratorId}/password`：使用 `password` 设置新密码。

## 4. 权限和秘密边界

- `PLATFORM_ADMIN` 仍只管理 Tenant，不能进入租户文档、API 调试或审计页面；
- `PLATFORM_ADMIN` 可读取公共使用说明，并在 Tenant 详情管理该租户的 `TENANT_ADMIN`，但这不授予其调用租户内部 Application、KnowledgeBase、Document 或查询接口的权限；
- `TENANT_ADMIN` 只管理自身租户；路径中的 Tenant、Application、KnowledgeBase、Document 和 Job 必须继续由后端复核；
- API 调试必须通过 Application Credential 和 Grant，管理员 Session 不能替代服务鉴权；
- 完整 Credential 仍只在创建时展示一次；调试页面不得自动从任何缓存恢复 Secret；
- DocQuery 不增加最终业务用户、部门或用户组授权；业务系统继续负责 Actor 对业务数据的权限。

## 5. 数据和依赖边界

- 复用 V1—V11 表和既有管理/服务 API，原则上不新增数据库迁移；
- 不修改 Compose，不增加新基础设施；
- 前端继续由 Maven 构建并打入同一个 Spring Boot JAR；
- OpenAPI 和 Postman 文件属于静态交付物，不成为运行时业务事实源；
- 文档状态、版本、任务、授权和审计始终以 MySQL 后端响应为准。

## 6. 失败处理

- 上传前校验文件存在、格式和 50 MiB 上限；服务端错误仍为最终事实；
- 上传、重试和删除都生成新的管理幂等键，网络不确定时不伪造成功；
- `PROCESSING`、`READY`、`FAILED`、`DELETING`、`DELETED` 使用不同中文状态，不混用 Document、Version 和 Job 状态；
- 只有 `failureRetryable=true` 的最终失败任务显示人工重试入口；
- 删除必须二次确认并明确不可恢复；删除失败不能恢复检索可见性；
- API 调试的 `401`、`404`、`409`、依赖失败和 HYBRID 降级必须保留稳定错误码与请求 ID；
- `401` 服务调用失败不能清除管理员 Session，因为两者是不同认证域。
- 新增管理员遇到全局登录名冲突返回 `409 ADMIN_LOGIN_CONFLICT`；目标不属于该 Tenant 返回 `404 TENANT_ADMIN_NOT_FOUND`；
- 停用最后一个有效租户管理员返回 `409 LAST_ACTIVE_TENANT_ADMIN`；并发停用通过锁定 Tenant 事实串行校验；
- 设置新密码成功后旧密码立即失效，账号既有 Session 因账号版本变化在下一请求返回 `401`。

## 7. 明确不做

- 多轮对话、Conversation 数据模型、历史摘要或流式回答；
- 正式公开数据集和真实供应商效果评测；
- 租户概览大屏和管理操作审计；
- 新角色、SSO、SDK、OCR、扫描件和图片理解；
- 租户管理员自助注册、邮件邀请、找回密码、删除管理员和租户内自定义角色；
- 新检索算法、新 Agent 工具或模型供应商；
- 独立前端部署、CORS 或云端托管。

## 8. 验收点

1. 平台管理员不能进入 N4.4 租户页面；租户管理员不能跨租户访问；
2. KnowledgeBase 页面可上传支持格式并看到 Document、Version、Job 的真实状态；
3. 新版本处理中明确显示旧 activeVersion 仍服务，成功后再切换；
4. 最终失败任务可查看原因并在允许时人工重试；
5. 删除受理后立即显示不可检索，清理成功进入 `DELETED`，失败时可受控重试；
6. API 调试通过真实 Credential + Grant 调用 Retrieve/Answer，没有管理员旁路；
7. Credential 不进入 URL、Web Storage、Query Cache 或日志；
8. Retrieve 展示 canonical Evidence，Answer 展示严格校验后的引用；
9. 查询后可以在审计页面找到对应请求事实，但看不到原问题和回答正文；
10. 平台管理员和租户管理员均可阅读使用说明并下载有效 OpenAPI/Postman 文件；
11. 平台管理员可在 Tenant 详情列出、新增、启停和重置租户管理员密码，租户管理员不能调用这些接口；
12. 最后一个有效租户管理员不可停用；状态变化或密码重置使其旧 Session 在下一请求失效；
13. 密码不进入响应、前端 Query Cache、URL、Web Storage 或日志；
14. 默认 Maven 回归、前端单测、静态资源测试和真实浏览器端到端通过；
15. 没有数据库迁移、`pom.xml`、Compose 或既有服务契约漂移。

## 9. 完成门禁

实现和验证完成后给出页面、外部文档、测试数量、真实依赖范围和未执行项，然后停止，等待用户明确说“确认 N4.4 完成”。用户已于 2026-08-15 给出该确认，N4.4 验收关闭；该确认不自动授权正式公开数据集评测或多轮 Agent。

## 10. 实施与验证结果

截至 2026-08-15，原冻结范围与租户管理员管理补充范围均已实现、完成验证并经用户验收：

- KnowledgeBase 详情已提供文档上传、列表、详情、版本历史、ProcessingJob、人工重试、逻辑删除和删除重试，并展示后端返回的真实状态；
- 已提供真实 Credential + Grant 的 Retrieve/Answer 调试页以及查询审计列表/详情；服务鉴权失败不会清除管理员 Session，Credential 只保存在调试组件局部内存；
- 已提供后台“使用说明”页面，集中展示接入顺序、ID 获取/复制入口、请求 Header、curl/Java 示例、错误处理，并可下载 OpenAPI YAML 和 Postman Collection；
- 平台管理员也可直接访问“使用说明”；Tenant 详情已提供租户管理员列表、新增、启停和密码重置，且不会回显密码；
- 管理接口仅允许平台管理员调用；最后一个有效租户管理员不可停用，密码重置和状态变化会使该账号既有 Session 在下一请求失效；
- OpenAPI 与 Postman 文件均已解析校验并随管理后台打入 Spring Boot JAR；仓库版本说明见 [`外部服务 API 接入说明`](../api/外部服务API接入说明.md)；
- 前端 Vitest 13/13 通过；默认 `mvnw clean verify` 共发现 148 项 Java 测试，146 项执行通过、2 项真实供应商冒烟按设计跳过，0 failure、0 error；其中 Surefire 43 项为 41 项通过、2 项跳过，Failsafe 105/105 通过；
- 使用临时 MySQL、SeaweedFS、RabbitMQ、Elasticsearch、Redis 和 Fake Gateway 完成真实浏览器端到端验证：平台管理员隔离、上传并处理至 `READY`、HYBRID Retrieve、带 canonical 引用的 Answer、最小化查询审计、新版本切换和删除至 `DELETED` 均通过；临时容器已清理，未触碰既有数据卷；
- 租户管理员补充范围另经真实浏览器验证：平台管理员可读使用说明并完成新增、重置密码、停用；最后一个有效管理员按钮受保护；租户管理员可登录并阅读说明，但不能访问 Tenant 管理或管理员管理；
- 本阶段未新增数据库迁移，未修改 `pom.xml` 或 `compose.yaml`，未执行正式公开数据集效果评测，也未实现多轮 Agent。
