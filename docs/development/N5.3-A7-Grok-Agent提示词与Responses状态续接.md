## 2. 协议验证

对 PackyAPI 实际模型 `grok-4.6` 的最小 Responses 冒烟确认：

- 支持 Function Calling；
- 支持 `store=false` 与 `include=["reasoning.encrypted_content"]`；
- 能返回加密 reasoning，并接受其后的无状态工具结果续接；
- 返回 Prompt Cache 命中 Token。

正确的无状态续接不是只发送“上一次 output + 新工具结果”，而是维护完整的追加式输入：原始
system/user、每轮 Responses output（含加密 reasoning）以及对应工具结果。第一次 A7 实现遗漏原始
任务上下文，因此该轮只作为故障诊断证据，不作为质量结果。

## 4. 结论

Responses 状态续接和缓存能力可用，但“更积极的提示词 + 正确的状态续接”没有改善这 5 题的
最终质量。`1032` 证明工具能够返回正确页和正确数值，模型仍可能漏掉题目要求的显式运算；
`0831`、`0937` 证明仅靠提示词也不能稳定避免过早停止。问题不能再简单归因于 DeepDoc、上下文
长度或 PackyAPI 协议。

因此 A7 不进入默认运行路径，不执行 20/80 题扩大评测。实验代码已回滚，A6 继续作为当前
运行基线；后续如继续优化，必须先冻结一个能机械约束“证据是否完整、任务是否完成”的最小
方案，而不是继续堆叠提示词或工具。
