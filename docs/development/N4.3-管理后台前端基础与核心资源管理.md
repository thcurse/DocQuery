# DocQuery N4.3 管理后台前端基础与核心资源管理

> 状态：已实现、验证并经用户验收  
> 前置阶段：N0—N4.2 已实现、验证并经用户验收  
> 本阶段门禁：用户已于 2026-08-12 明确说“确认开始 N4.3”

## 1. 阶段目标

N4.3 首次交付可运行的管理后台前端，让平台管理员和租户管理员能够通过浏览器完成 N1 已有核心资源管理。前端与 Spring Boot 同源部署在 `/admin/`，沿用既有服务端 Session、CSRF、角色和租户隔离，不另建认证体系或 Node 服务。

## 2. 产品范围

### 2.1 平台管理员

- 管理员登录、当前身份和退出；
- 租户列表、创建、详情、修改名称和启停；
- 创建租户时录入首个租户管理员账号和密码，密码不回显、不保存。

### 2.2 租户管理员

- 管理员登录、当前租户上下文和退出；
- 应用列表、创建、详情、修改和启停；
- 应用 Credential 列表、创建和撤销；
- 应用到知识库的 Grant 查看、新增或修改、撤销；
- 知识库列表、创建、详情、修改和启停；
- 从知识库详情查看和管理已授权应用。

## 3. 服务契约和权限边界

- 使用既有 `/api/admin/v1/**` 契约，不改变 `/retrieve`、`/answer`；
- `/auth/me` 是页面恢复身份的唯一事实来源，`tenantId` 只取后端响应；
- `PLATFORM_ADMIN` 只进入租户管理，`TENANT_ADMIN` 只进入自身租户的应用、Credential、Grant 和知识库管理；
- 页面隐藏不是权限控制，后端继续执行角色、Session 有效性和路径租户复核；
- 不增加知识库管理员、接入开发者、普通业务用户、部门或用户组角色；
- 列表名称映射和前端筛选通过既有分页接口逐页读取完成，不增加数据库表或管理查询字段。

## 4. 会话、CSRF 和秘密处理

- 所有请求使用同源 Cookie，前端不接触 `JSESSIONID`；
- 登录前读取 `/auth/csrf`，写请求携带服务端声明的 Header；
- 登录成功发生 Session ID 轮换，立即丢弃旧 CSRF 并重新获取；
- `401` 清空内存身份并回到登录页，`403` 展示无权限页；
- CSRF 只保存在运行内存；
- 完整应用 Credential 只保存在创建请求的局部状态，并通过一次性弹窗显示；弹窗关闭即清除，禁止写入 URL、Web Storage、TanStack Query Cache 或日志；
- 租户初始管理员密码由平台管理员输入，创建响应不回传，前端提交后立即清空。

## 5. 前端技术和交付形态

- React + TypeScript + Vite；
- React Router Data Mode；
- TanStack Query 管理服务端状态；
- Ant Design 构建可访问的 B 端界面；
- Vitest + React Testing Library 做单元/组件测试；
- Playwright 做浏览器验收；
- Maven 调用本机 Node/npm 完成确定性安装、测试和构建；
- 构建产物复制到 Spring Boot `static/admin`，最终只有一个 JAR 和一个应用进程。

## 6. 页面与交互

- 登录页明确这是管理员入口，没有注册、应用 Credential 登录或平台初始化入口；
- 桌面布局沿用既有界面稿的蓝色侧栏、白色工作区和克制的信息密度；
- 顶部始终显示登录账号、角色和当前租户；
- 状态、环境和权限使用中文业务文案，同时在详情处保留稳定编码；
- 停用、撤销等不可逆或有业务影响的操作必须二次确认；
- 应用详情同时提供 Credential 和知识库授权；知识库详情提供已授权应用；
- 列表具备全局筛选、排序和分页，不把“应用”描述为最终业务用户。

## 7. 失败处理

- 字段校验错误就近显示；稳定后端错误码映射为中文提示，未知错误保留错误码；
- 网络错误允许用户重试，不伪造成功状态；
- 写入成功后失效相关 Query 并重新读取后端事实；
- `401` 统一结束当前前端会话；`403` 不通过自动跳转或重试绕过；
- 一次性 Credential 创建响应即使后续列表刷新失败也只显示一次，绝不放入可重放缓存；
- 页面级加载、空状态和失败状态均可区分。

## 8. 本阶段明确不做

- 租户概览、查询审计和管理操作审计页面；
- 管理操作审计后端；
- 新角色、注册、SSO、Refresh Token、Remember Me 或前端保活；
- `/retrieve`、`/answer` 调试台和售后工单 Demo；
- 独立前端部署、CORS、云端托管或独立 Node 运行时；
- N5 故障、负载、成熟公开数据集和真实供应商效果评测。

## 9. 验收点

1. 匿名访问 `/admin/` 进入登录页，错误登录不泄露账号状态；
2. 登录后 Session 轮换场景仍能用新 CSRF 完成写操作；
3. 平台管理员可创建、查询、修改、启停租户，不能进入租户管理员资源页；
4. 租户管理员只能管理自身租户，当前租户始终可见；
5. 应用和知识库可创建、查看、修改、启停；
6. Credential 可创建、查看摘要和撤销，完整值只出现一次且不进入持久化存储、URL或缓存；
7. 可从应用和知识库两个视角管理同一 Grant，权限和状态一致；
8. 停用、撤销操作有清楚影响说明和二次确认；
9. `401`、`403`、验证错误、网络失败、空列表和加载状态有明确页面行为；
10. 前端单测、Spring Boot 静态资源集成测试和 Playwright 核心流程通过；
11. `mvn clean verify` 同时执行前端安装、测试、构建和既有 Java 全量回归；
12. 打包 JAR 内包含 `/admin/` 静态资源，生产无需独立 Node 服务。

## 11. 实现结果

- `frontend` 已落地 React、TypeScript、Vite、React Router Data Mode、TanStack Query 和 Ant Design；平台管理员与租户管理员共享同一登录入口，并按后端身份恢复各自路由。
- 平台管理员页面已覆盖租户列表、创建、详情、名称修改和启停；租户管理员页面已覆盖 Application、KnowledgeBase、Credential 和 Grant 的列表、创建、详情、修改、启停、撤销及双向授权管理。
- 前端沿用同源 `HttpSession` 和 CSRF：登录后重新取得 CSRF，`401` 清理内存身份，`403` 展示无权限结果，路由隐藏不替代后端鉴权。
- 完整 Credential 仅进入创建请求的局部状态和一次性弹窗；弹窗关闭即清除，自动化测试确认不会写入 URL、`localStorage` 或 `sessionStorage`。租户初始管理员密码不进入 Query Cache，提交后立即重置表单。
- Maven 在 `generate-resources` 执行确定性 `npm ci` 和前端构建，在 `test` 执行前端测试，再将产物复制到 Spring Boot `static/admin`；生产交付仍为一个 JAR、一个应用进程，无需独立 Node 服务。
- 本阶段没有新增数据库迁移，没有修改 Compose，也没有改变 `/retrieve`、`/answer` 或管理 API 服务契约。
