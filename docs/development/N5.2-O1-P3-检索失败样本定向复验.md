## 6. 评测有效性新发现

1. MMLongBench-Doc 的问题是在“已经给定单份长文档”的任务设定下编写。`What is the title of the slide?`、`Which individual lead this program?` 等问题本身不足以在 100 份文档中唯一定位来源；不传 `documentIds` 时，Document Hit 不能直接与该公开数据集原任务横向比较。
2. 数据集中 `NYU_graduate.pdf` 与 `mi_phone.pdf` 的文件大小和 SHA-256 完全相同，却被分配了不同 documentKey。内容检索无法可靠区分两个标签，NYU 两题的文档排名受重复文档污染。
3. MMLongBench-Doc 的 NYU Gold 页使用 PDF 内印刷页码：Gold 21/28 分别位于 PDF 物理页 23/30；DocQuery API 返回物理页码。冻结算法直接比较两套坐标，把已经返回的正确证据页计为 miss。
4. 当前只验证了 NYU 两个页码映射，不能据此修正 54 题总体分数。既有 R2 原始结果保留，但 Page Coverage 系列指标在完成逐文档页码坐标映射前必须标记为 `VALIDITY_LIMITATION`。

本次结果证明“只重建并恢复标题”不足以解决跨文档检索问题，同时暴露了公开数据集任务设定、重复文件和页码坐标三项评测设计问题。下一步必须先重新冻结评测口径，不继续盲目调整解析器或执行 Answer。
